# 虛構設備異常紀錄整理器 v0.1

以虛構設備紀錄示範資料驗證、狀態分類與摘要輸出的 Python 小作品。

版本狀態：v0.1 展示版，已完成固定六筆虛構資料基準驗收。

## 功能

- 檢查紀錄是否包含 `id` 與 `status`。
- 將有效紀錄分為 `pending`、`processing`、`completed`。
- 將缺少必要欄位或狀態不在分類規則內的紀錄保留在未知分類，顯示對應原因。
- 顯示總紀錄數、各分類數量與完成率。
- 依序提示：檢查未知狀態 → 追蹤處理中紀錄 → 開始處理待處理紀錄；若皆無則顯示目前沒有待處理工作。

完成率以「已完成數量 ÷ 總紀錄數 × 100」計算，總紀錄數包含未知分類，顯示至小數點後一位。

## 正常執行

使用 Python 3。手機操作方式：在 Pydroid 3 開啟並儲存 `alarm_record_tool_v2.py`，按下執行鍵。

檔案最底下的預設入口應為：

```python
if __name__ == "__main__":
    main()
```

`main()` 負責整理與顯示資料，不呼叫固定六筆資料的驗收函式。

## 手動驗收

`run_v01_test()` 會將目前的 `records` 分類、建立摘要，再交由 `validate_v01()` 核對六項基準。

1. 暫時將檔案最底下的入口改為下方程式碼。
2. 儲存並以一般 Python 模式執行；驗收使用 `assert`，不使用 `-O` 最佳化模式。
3. 確認顯示 `v0.1 基準驗收：PASS`。
4. 驗收後將最底下的呼叫改回 `main()`，並儲存。

```python
if __name__ == "__main__":
    run_v01_test()
```

固定範例的預期結果：

| 驗收項目 | 預期值 |
| --- | --- |
| 總紀錄數 | 6 |
| 待處理數量 | 1 |
| 處理中數量 | 1 |
| 已完成數量 | 1 |
| 未知狀態數量 | 3 |

三筆未知紀錄分別涵蓋：狀態值不在分類規則內、缺少 `status`、缺少 `id`。

任一基準不符會觸發 `AssertionError`。這是固定範例的回歸驗收；若主動更改 `records`，應重新確認預期結果。正常資料處理不要求紀錄必須剛好六筆。
